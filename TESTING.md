# Тестирование страницы оплаты

## 1. Модульные тесты

### Валидация `card_number`
- Если длина `card_number` не равна 16 символам, метод возвращает `400` с сообщением **"Некорректный номер карты"**.
- Если `card_number` содержит нецифровые символы, метод возвращает `400` с сообщением **"Некорректный номер карты"**.

### Валидация `card_holder`
- Если `card_holder` пустой, метод возвращает `400` с сообщением **"Имя владельца карты не может быть пустым"**.
- Если `card_holder` содержит более одного пробела подряд, метод возвращает `400` с сообщением **"Некорректное имя владельца карты"**.
- Если `card_holder` содержит символы, не соответствующие латинице или дефису, метод возвращает `400` с сообщением **"Имя владельца карты должно быть на латинице"**.

### Валидация `card_expiration`
- Если `card_expiration` пустой, метод возвращает `400` с сообщением **"Срок действия карты не может быть пустым"**.
- Если формат `card_expiration` не соответствует `мм/гг`, метод возвращает `400` с сообщением **"Некорректный формат срока действия карты"**.
- Если срок действия карты истёк, метод возвращает `400` с сообщением **"Срок действия карты истёк"**.

### Валидация `cvv`
- Если `cvv` не состоит из трёх цифр, метод возвращает `400` с сообщением **"Некорректный CVV-код"**.

### Валидация `order_number`
- Если `order_number` пустой, метод возвращает `400` с сообщением **"Номер заказа не может быть пустым"**.
- Если длина `order_number` превышает 16 символов, метод возвращает `400` с сообщением **"Превышена длина номера заказа"**.

### Валидация `sum`
- Если `sum` не является строкой в формате "число,число", метод возвращает `400` с сообщением **"Некорректный формат суммы"**.
- Если `sum` меньше или равно 0, метод возвращает `400` с сообщением **"Некорректная сумма оплаты"**.

Если передаем валидные данные во все поля, то метод должен возвращать ответ с http-кодом 200.

## 2. Интеграционные тесты

### Проверка связки "фронт-бэк"

#### 1. Некорректный `card_number`
- Если `card_number` невалидный, поле **"Номер карты"** выделяется красной рамкой и отображается сообщение **"Некорректный номер карты"**.

#### 2. Истёкший `card_expiration`
- Если срок действия карты истёк, поле **"Срок действия"** выделяется красной рамкой и отображается сообщение **"Срок действия карты истёк"**.

### Проверка связки "бэк-сервис A"

#### 1. Ошибка списания
- Если сервис A возвращает `403`, бэк возвращает `403` с сообщением **"Не удалось списать средства с карты"**.

#### 2. Успешное списание
- Если сервис A возвращает `200`, вызывается метод `setOrderIsPaid` с переданными `order_number` и `sum`.

### Проверка связки "бэк-репозиторий"

#### 1. Успешное обновление заказа
- Если `setOrderIsPaid` возвращает `true`, метод контроллера отвечает `200` с сообщением **"Оплата успешно выполнена"**.

#### 2. Ошибка при обновлении
- Если `setOrderIsPaid` выбрасывает исключение, метод контроллера отвечает `500` с сообщением **"Ошибка при обновлении статуса заказа"**.

## 3. Системные тесты

### 1. Проверка сценария успешной оплаты
- Ввести корректные данные карты, валидный `order_number` и `sum`.
- Убедиться, что плата списана, заказ обновлён, и отображено сообщение **"Оплата успешно выполнена"**.

### 2. Проверка ошибки при недостатке средств
- Ввести корректные данные карты, при которых сервис A вернёт `403`.
- Убедиться, что на фронте отображено сообщение **"Не удалось списать средства с карты"**.

### 3. Проверка восстановления при сбое
- Ввести корректные данные, но симулировать сбой в методе `setOrderIsPaid`.
- Убедиться, что на фронте отображается сообщение **"Ошибка при обновлении статуса заказа"**.

### 4. Проверка ошибок формата данных
- Ввести невалидный `cvv` (например, 12 или abc).
- Убедиться, что поле **"CVV"** выделено красной рамкой и отображается сообщение **"Некорректный CVV-код"**.

### 5. Проверка валидации суммы
- Ввести отрицательное значение в поле **"Сумма"**.
- Убедиться, что поле **"Сумма"** выделено красной рамкой и отображается сообщение **"Некорректная сумма оплаты"**.
