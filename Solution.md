# Тесты бэкенда страницы оплаты

## 1. Модульные тесты (Unit Tests)
>Модульные тесты проверяют правильность валидации входных данных. Если входные данные валидны, возвращаем HTTP-code 200

### 1.1. Проверка поля *card_number*:
#### Testcases:
* поле пустое -> HTTP-code 400 (сообщение "Укажите № карты")
* количество символов > 16  -> HTTP-code 400 (сообщение "Неверный № карты")
* количество символов < 16  -> HTTP-code 400 (сообщение "Неверный № карты")
* поле содержит не только цифры -> HTTP-code 400 (сообщение "№ карты должен состоять только из цифр")

### 1.2. Проверка поля *card_holder*:
#### Testcases:
* поле пустое -> HTTP-code 400 (сообщение "Укажите фамилию и имя владельца карты")
* поле содержит не только латиницу, пробел и дефис -> HTTP-code 400 (сообщение "Неверный формат имени владельца")

### 1.3. Проверка поля *card_expiration*:
#### Testcases:
* поле пустое -> HTTP-code 400 (сообщение "Укажите дату окончания срока действия карты")
* не в формате мм/гг -> HTTP-code 400 (сообщение "Неверный формат даты окончания срока действия карты")
* прошедшая дата окончания срока действия карты  -> HTTP-code 400 (сообщение "Срок действия карты истек")

### 1.4. Проверка поля *cvv*:
#### Testcases:
* поле пустое -> HTTP-code 400 (сообщение "Укажите cvv карты")
* количество символов > 3  -> HTTP-code 400 (сообщение "Неверный cvv карты")
* количество символов < 3  -> HTTP-code 400 (сообщение "Неверный cvv карты")
* поле содержит не только цифры -> HTTP-code 400 (сообщение "cvv карты должен состоять только из цифр")

### 1.5. Проверка поля *order_number*:
#### Testcases:
* поле пустое -> HTTP-code 400 (сообщение "Укажите номер заказа")
* количество символов > 16  -> HTTP-code 400 (сообщение "Неверный формат номера заказа")

### 1.6. Проверка поля *sum*:
#### Testcases:
* поле пустое -> HTTP-code 400 (сообщение "Укажите сумму заказа")
* отрицательное значение -> HTTP-code 400 (сообщение "Сумма заказа не может быть отрицательным значением")

## 2. Интеграционные тесты (Integration Tests)
>Проверяем взаимодействие между модулями.

### 2.1. Frontand - Backend
#### Testcases:
* любое поле пустое или невалидное -> HTTP-code 400 (рамка поля выделяется красным, а в подсказке появляется красный текст с текстом ошибки, описанной в разделе Unit Tests)
* если все данные валидные -> HTTP-code 200, направляется запрос в Service A

### 2.2. Backend - Service A
#### Testcases:
* Не удалось списать деньги -> HTTP-code 403 (сообщение "Не удалось списать денежные средства")
* Удалось списать деньги -> HTTP-code 200 (запись в базу данных информацию о списании)

### 2.3. Backend - Repository
#### Testcases:
* метод setOrderIsPaid выбросил исключение -> HTTP-code 500 (сообщение "Ошибка записи оплаты")
* метод setOrderIsPaid вернул true -> HTTP-code 200 (сообщение "Оплата прошла успешно")

## 3. Системные тесты (System Tests)
>Проверка работы всей системы
#### Testcases:
* Недостаточно денег на счете -> всплывающее модульное окно с текстом "Оплата не прошла - недостаточно денег на счете"
* Оплата прошла успешно -> всплывающее модульное окно с текстом "Оплата прошла!"

## 4. Способы удешевления тестирования
* Использование моков - вместо реальных транзакция можно использовать моки
* CI/CD - автоматизация тестирования
