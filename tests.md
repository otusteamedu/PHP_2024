# Модульные тесты

### Проверка наличия обязательных полей
- Если отсутствует хотя бы одно обязательное поле, метод возвращает **400** с соответствующим сообщением об ошибке.

### Проверка формата обязательных полей
- **`card_number`:**
    - Если длина не равна 16 символам, метод возвращает **400** с сообщением об ошибке.
    - Если содержит символы, отличные от цифр, метод возвращает **400** с сообщением об ошибке.
- **`card_holder`:**
    - Если тип данных не `string`, метод возвращает **400** с сообщением об ошибке.
    - Если содержит символы, отличные от латинских букв, пробелов или дефиса, метод возвращает **400** с сообщением об ошибке.
    - Если содержит более одного пробела подряд, метод возвращает **400** с сообщением об ошибке.
- **`card_expiration`:**
    - Если формат отличается от `мм/гг`, метод возвращает **400** с сообщением об ошибке.
    - Если срок действия карты истёк, метод возвращает **400** с сообщением об ошибке.
    - Если месяц указан вне диапазона 1–12, метод возвращает **400** с сообщением об ошибке.
- **`cvv`:**
    - Если длина отличается от 3 символов, метод возвращает **400** с сообщением об ошибке.
    - Если содержит символы, отличные от цифр, метод возвращает **400** с сообщением об ошибке.
- **`order_number`:**
    - Если длина превышает 16 символов, метод возвращает **400** с сообщением об ошибке.
- **`sum`:**
    - Если значение меньше или равно 0, метод возвращает **400** с сообщением об ошибке.
    - Если содержит символы, отличные от цифр и запятой, метод возвращает **400** с сообщением об ошибке.
    - Если содержит более одной запятой, метод возвращает **400** с сообщением об ошибке.

### Обработка успешного результата
- Если все поля заполнены корректно, метод возвращает **200**.

# Интеграционные тесты

### Связка фронт–бекенд
- **`card_number`:**
    - Если поле заполнено некорректно или отсутствует, фронт выделяет поле красным и выводит соответствующее сообщение.
- **`card_holder`:**
    - Если поле заполнено некорректно или отсутствует, фронт выделяет поле красным и выводит соответствующее сообщение.
- **`card_expiration`:**
    - Если поле заполнено некорректно или отсутствует, фронт выделяет поле красным и выводит соответствующее сообщение.
- **`cvv`:**
    - Если поле заполнено некорректно или отсутствует, фронт выделяет поле красным и выводит соответствующее сообщение.

### Связка бекенд–сервис A
- Если сервис A возвращает **403**, бекенд возвращает на фронт код **400** с соответствующим сообщением об ошибке.
- Если сервис A возвращает **200**, бекенд передаёт фронту код **200** с сообщением об успешной операции.

### Связка бекенд–репозиторий
- Если метод `setOrderIsPaid` выбрасывает исключение, бекенд должен обработать ошибку и вернуть фронту код 500 с соответствующим сообщением об ошибке.
- Если метод `setOrderIsPaid` возвращает `true`, бекенд завершает процесс с кодом **200** и сообщением об успехе.

# Системные тесты

### Успешная оплата
- Если сервис A возвращает **200**, данные корректны, оплата проходит успешно:
    - В базе данных фиксируется запись с правильным номером заказа и суммой.
    - На фронте отображается сообщение об успехе.

### Ошибка на бекенде или в сервисе A
- Если происходит сбой (например, ошибка сервера **500**), на фронте отображается сообщение **"Внутренняя ошибка, повторите попытку позже"**, а транзакция не завершается.

### Неудачная попытка списания
- Если обязательные поля не прошли проверку или сервис A блокирует транзакцию:
    - На фронте отображается сообщение об ошибке с текстом, подходящим для конкретного случая.
    - Поле, вызвавшее ошибку, подсвечивается красным.
