# Домашнее задание к вебинару №23 «Unit-тестирование»

## Кейсы тестирования

### 1. Модульные тесты (Unit-тесты)

#### Валидация данных:
- **a.** Если `card_number` содержит не 16 цифр, возвращается ошибка 400 с сообщением "Номер карты должен содержать 16 цифр".
- **b.** Если `card_holder` содержит более одного пробела или недопустимые символы, возвращается ошибка 400 с сообщением "Некорректное имя владельца карты".
- **c.** Если `card_expiration` имеет неверный формат (не "мм/гг"), возвращается ошибка 400 с сообщением "Некорректный срок действия карты".
- **d.** Если `cvv` содержит не 3 цифры, возвращается ошибка 400 с сообщением "Некорректный CVV-код".
- **e.** Если `order_number` пустой или превышает 16 символов, возвращается ошибка 400 с сообщением "Некорректный номер заказа".
- **f.** Если `sum` содержит неверный формат (например, буквы вместо цифр), возвращается ошибка 400 с сообщением "Некорректная сумма оплаты".

#### Взаимодействие с сервисом A:
- **g.** Если сервис A возвращает код 200, метод возвращает успешный ответ.
- **h.** Если сервис A возвращает код 403, метод возвращает ошибку 403 с сообщением "Не удалось списать средства".

#### Взаимодействие с репозиторием:
- **i.** Если метод `setOrderIsPaid` возвращает `true`, метод возвращает успешный ответ.
- **j.** Если метод `setOrderIsPaid` выбрасывает исключение, метод возвращает ошибку 500 с сообщением "Ошибка при сохранении данных".

---

### 2. Интеграционные тесты

#### Связка "фронт-бэк":
- **a.** Если `card_holder` содержит более одного пробела, фронт выделяет поле "Имя владельца карты" красной рамкой и выводит сообщение "Некорректное имя владельца карты".
- **b.** Если `card_expiration` имеет неверный формат, фронт выделяет поле "Срок действия карты" красной рамкой и выводит сообщение "Некорректный срок действия карты".

#### Связка "бэк-сервис A":
- **c.** Если сервис A возвращает код 200, бэк возвращает успешный ответ на фронт.
- **d.** Если сервис A возвращает код 403, бэк возвращает ошибку 403 с сообщением "Не удалось списать средства".

#### Связка "бэк-репозиторий":
- **e.** Если метод `setOrderIsPaid` возвращает `true`, бэк возвращает успешный ответ на фронт.
- **f.** Если метод `setOrderIsPaid` выбрасывает исключение, бэк возвращает ошибку 500 с сообщением "Ошибка при сохранении данных".

---

### 3. Системные тесты

#### Успешная оплата:
- **a.** Пользователь вводит корректные данные, сервис A возвращает код 200, репозиторий успешно сохраняет данные, фронт отображает сообщение "Оплата прошла успешно".

#### Ошибка при списании средств:
- **b.** Пользователь вводит корректные данные, но сервис A возвращает код 403, фронт отображает сообщение "Не удалось списать средства, проверьте реквизиты".

#### Ошибка при сохранении данных:
- **c.** Пользователь вводит корректные данные, сервис A возвращает код 200, но репозиторий выбрасывает исключение, фронт отображает сообщение "Ошибка при сохранении данных".

#### Ошибка валидации данных:
- **d.** Пользователь вводит неверный формат `card_expiration`, фронт выделяет поле "Срок действия карты" красной рамкой и выводит сообщение "Некорректный срок действия карты".
