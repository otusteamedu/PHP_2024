### Кейсы тестирования для задачи оплаты

#### 1. Модульные тесты (тестирование бэка):
Модульные тесты проверяют корректность валидации данных и логику обработки ошибок.

**a. Валидация `card_number`:**
- Если `card_number` пустой, возвращается ошибка 400 с сообщением "Номер карты не может быть пустым".
- Если `card_number` содержит нечисловые символы, возвращается ошибка 400 с сообщением "Номер карты должен содержать только цифры".
- Если `card_number` содержит меньше или больше 16 цифр, возвращается ошибка 400 с сообщением "Номер карты должен содержать 16 цифр".
- Если `card_number` содержит ровно 16 цифр, данные считаются валидными.

**b. Валидация `card_holder`:**
- Если `card_holder` пустой, возвращается ошибка 400 с сообщением "Имя владельца карты не может быть пустым".
- Если `card_holder` содержит более одного пробела, возвращается ошибка 400 с сообщением "Имя владельца карты должно содержать только одно пробельное разделение".
- Если `card_holder` содержит нелатинские символы, возвращается ошибка 400 с сообщением "Имя владельца карты должно быть написано латиницей".
- Если `card_holder` содержит имя и фамилию латиницей, разделённые одним пробелом, данные считаются валидными.

**c. Валидация `card_expiration`:**
- Если `card_expiration` пустой, возвращается ошибка 400 с сообщением "Срок действия карты не может быть пустым".
- Если `card_expiration` не соответствует формату "мм/гг", возвращается ошибка 400 с сообщением "Неверный формат срока действия карты".
- Если срок действия карты истёк, возвращается ошибка 400 с сообщением "Срок действия карты истёк".
- Если `card_expiration` соответствует формату "мм/гг" и срок действия не истёк, данные считаются валидными.

**d. Валидация `cvv`:**
- Если `cvv` пустой, возвращается ошибка 400 с сообщением "CVV не может быть пустым".
- Если `cvv` содержит меньше или больше 3 цифр, возвращается ошибка 400 с сообщением "CVV должен содержать 3 цифры".
- Если `cvv` содержит нечисловые символы, возвращается ошибка 400 с сообщением "CVV должен содержать только цифры".
- Если `cvv` содержит ровно 3 цифры, данные считаются валидными.

**e. Валидация `order_number`:**
- Если `order_number` пустой, возвращается ошибка 400 с сообщением "Номер заказа не может быть пустым".
- Если `order_number` содержит более 16 символов, возвращается ошибка 400 с сообщением "Номер заказа не может превышать 16 символов".
- Если `order_number` содержит от 1 до 16 символов, данные считаются валидными.

**f. Валидация `sum`:**
- Если `sum` пустой, возвращается ошибка 400 с сообщением "Сумма оплаты не может быть пустой".
- Если `sum` содержит некорректный формат (например, два разделителя), возвращается ошибка 400 с сообщением "Неверный формат суммы".
- Если `sum` меньше или равна нулю, возвращается ошибка 400 с сообщением "Сумма оплаты должна быть больше нуля".
- Если `sum` содержит корректный формат (например, "100,50") и значение больше нуля, данные считаются валидными.

**g. Все данные корректны (позитивный сценарий):**
- Если все поля формы содержат корректные данные, метод возвращает успешный ответ (код 200) и передаёт данные для дальнейшей обработки (сервис A).

#### 2. Интеграционные тесты:
Интеграционные тесты проверяют взаимодействие между модулями.

**a. Связка "фронт-бэк":**
- Если `field_name` формы невалиден, фронт выделяет поле красной рамкой и отображает сообщение об ошибке.

**b. Связка "бэк-сервис A":**
- Если сервис A возвращает код 403 (ошибка списания), бэк возвращает фронту ошибку 403 с сообщением "Не удалось списать средства".
- Если сервис A возвращает код 200 (успешное списание), бэк передаёт данные в репозиторий.

**c. Связка "бэк-репозиторий":**
- Если метод `setOrderIsPaid` возвращает `true`, бэк возвращает фронту код 200 с сообщением "Оплата успешно завершена".
- Если метод `setOrderIsPaid` выбрасывает исключение, бэк возвращает фронту код 500 с сообщением "Ошибка при обработке заказа".

---

#### 3. Системные тесты:
Системные тесты проверяют работу системы в целом, включая взаимодействие всех модулей и пользовательский опыт.

**a. Успешная оплата:**
- Пользователь вводит корректные данные, сервис A возвращает код 200, репозиторий подтверждает оплату, фронт отображает сообщение "Оплата успешно завершена".

**b. Ошибка списания средств:**
- Пользователь вводит корректные данные, но сервис A возвращает код 403, фронт отображает сообщение "Не удалось списать средства, проверьте реквизиты".

**c. Ошибка в данных карты:**
- Пользователь вводит неверный `cvv`, фронт отображает сообщение "Неверный CVV, проверьте реквизиты".

**d. Ошибка в репозитории:**
- Пользователь вводит корректные данные, сервис A возвращает код 200, но репозиторий выбрасывает исключение, фронт отображает сообщение "Ошибка при обработке заказа, попробуйте позже".
