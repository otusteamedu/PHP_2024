# Разработка кейсов тестирования

## Модульные тесты
1. Валидация card_number:
   1. Если card_number содержит любые символы, кроме цифр, то тестируемый метод возвращает 400 с сообщением об ошибке "Поле номер карты должен содержать только цифры";
   2. Если card_number содержит более 16 цифр, то тестируемый метод возвращает 400 с сообщением об ошибке "Поле номер карты должен содержать 16 цифр";
   3. Если card_number содержит менее 16 цифр, то тестируемый метод возвращает 400 с сообщением об ошибке "Поле номер карты должен содержать 16 цифр" ;
   4. Если card_number содержит 16 цифр, то данные считаются валидными.
2. Валидация card_holder
   1. Если card_holder содержит более одного пробела, то тестируемый метод возвращает 400 с сообщением об ошибке "Поле владелец карты должен содержать один пробел";
   2. Если card_holder не содержит пробелов, то тестируемый метод возвращает 400 с сообщением об ошибке "Поле владелец карты должен содержать один пробел";
   3. Если card_holder содержит какие-то символы кроме латиницы и дефиса, то тестируемый метод возвращает 400 с сообщением об ошибке "Поле владелец карты должно содержать только латинские символы и дефис";
   4. Если card_holder содержит менее двух слов (словами является последовательность из латинских символов и дефисов), то тестируемый метод возвращает 400 с сообщением об ошибке "Поле владелец карты должно содержать имя и фамилию";
   5. Если card_holder содержит два слова и проходит предыдущие проверки, то данные считаются валидными.
3. Валидация card_expiration
   1. Если card_expiration не соответствует формату "мм/гг", возвращается ошибка 400 с сообщением "Поле срок действия карты содержит неверный формат";
   2. Если срок действия карты истёк, возвращается ошибка 400 с сообщением "Срок действия карты истёк";
   3. Если срок действия карты проходит проверки выше, то данные считаются валидными.
4. Валидация cvv
   1. Если cvv содержит меньше или больше 3 цифр, возвращается ошибка 400 с сообщением "Поле CVV должно содержать 3 цифры";
   2. Если cvv содержит нечисловые символы, возвращается ошибка 400 с сообщением "Поле CVV должно содержать только цифры";
   3. Если cvv содержит ровно 3 цифры, данные считаются валидными.
5. Валидация order_number
   1. Если order_number пустое, то возвращается ошибка 400 с сообщением "Поле номер заказа должно быть заполнено";
   2. Если order_number содержит менее 1 или более 16 символов, возвращается ошибка 400 с сообщением "Поле номер заказа не может превышать 16 символов";
   3. Если order_number содержит от 1 до 16 символов, данные считаются валидными.
6. Валидация sum
   1. Если sum пустой, возвращается ошибка 400 с сообщением "Поле сумма оплаты не может быть пустой";
   2. Если sum меньше или равна нулю, возвращается ошибка 400 с сообщением "Поле сумма оплаты должна быть больше нуля";
   3. Если sum содержит более чем 1 разделитель, то возвращается ошибка 400 с сообщением "Поле сумма оплаты содержит неверный формат";
   4. Если sum содержит любые символы, кроме цифр и разделителя, то возвращается ошибка 400 с сообщением "Поле сумма оплаты содержит неверный формат";
   5. Если sum проходит все проверки выше, то данные считаются валидными.
7. Все валидации пройдены
   1. Если все проверки пройдены, то тестируемый метод возвращает код 200 (успешный ответ) и передает данные для дальнейшей обработки в платежный сервис А

## Интеграционные тесты
1. Связка фронт-бек
   1. Если при проверке полей какое-то из полей не валидно, то на фронте это поле выделяется красным и под ним пишется текст ошибки;
   2. Если при проверке полей все поля, валидны, то пропадают ошибки если они были и бек отрабатывает дальше.
2. Связка бек-платежный сервис А
   1. Если сервис А возвращает код 403 (ошибка списания), то бек возвращает фронту ошибку 403 с сообщением "Не удалось списать средства";
   2. Если сервис А возвращает код 200, то бек передает данные в репозиторий.
3. Связка бек-репозиторий
   1. Если метод setOrderIsPaid выбрасывает исключение, то бек отменяет финансовую транзакцию (тут не уверен) и возвращает фронту код 500 с сообщением "Ошибка при обработке заказа";
   2. Если метод setOrderIsPaid возвращает true, то бек возвращает фронту код 200 сообщение "Оплата успешно завершена".

## Системные тесты
1. Ошибка в данных карты
   1. Пользователь вводит неверные данные на этапе заполнения формы и получает соответствующие ошибки в неверных полях. 
2. Ошибка списания средств
   1. Пользователь вводит верные данные, но на тестовой карте недостаточно средств для покупки, поэтому сервис возвращает ошибку 403, которую backend передает на фронт и фронт отображает соответствующую ошибку "Не удалось списать средства".
3. Ошибка в репозитории
   1. Пользователь пытается купить тестовый фильм стоимостью 1 рубль, далее вводит правильные данные, платежный сервис A возвращает код 200, но репозиторий выбрасывает исключение, фронт отображает сообщение "Ошибка при обработке заказа", а на карте пользователя не изменяется баланс.
4. Успешная оплата
   1. Пользователь пытается купить тестовый фильм стоимостью 1 рубль, далее вводит правильные данные, платежный сервис А отдает успешный ответ, репозиторий отдает успешный ответ и пользователь видит сообщение о том, что "Оплата успешно проведена" и может просмотреть тестовый фильм.
