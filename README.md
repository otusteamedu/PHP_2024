# Домашнее задание №20  
## Проектирование API
### Цель:
Научиться создавать универсальный интерфейс для различных потребителей (frontend фреймворки, мобильные приложения, сторонние приложения)

### Описание/Пошаговая инструкция выполнения домашнего задания:

Необходимо реализовать Rest API с использованием очередей.

Ваши клиенты будут отправлять запросы на обработку, а вы будете складывать их в очередь и возвращать номер запроса.

В фоновом режиме вы будете обрабатывать запросы, а ваши клиенты периодически, используя номер запроса, будут проверять статус его обработки.


Разрешается

- Использование Composer-зависимостей
- Использование микрофреймворков (Lumen, Silex и т.п.)

### Критерии оценки:

- 5 баллов за реализацию API
- 3 балла за применение очередей
- 2 балла за документацию (например, в Swagger)

## Решение
Решение реализовано в виде REST API сервиса.
Сервис реализован в формате чистой архитектуры, с разделением по слоям.
За основу сервиса взят фреймворк Laravel 11. Для запуска используются docker-контейнеры.
Для хранения данных используется БД MySQL. В качестве веб-сервера использован Nginx.
В качестве брокера очередей использован RabbitMQ.

Документация API оформлена в виде аннотаций в файле ApiController.php.
Для генерации файла использована библиотека darkaonline/l5-swagger.
Сгенерированный файл документации находится здесь public/docs/api-docs.json
Также можно зайти на страницу Swagger-документации по адресу http://mysite.local/api/documentation.
Сгенерированный файл api-docs.json уже включен в проект, в случае необходимости его можно перегенерировать командой php artisan l5-swagger:generate


### Краткое описание алгоритма работы
Поступившая заявка сохраняется в БД и после этого сразу отправляется в очередь, после чего 
статус заявки в БД меняется на "queued". Из очереди заявки получает консьюмер 
(необходимо отдельно запустить командой php artisan app:consumer) 
и передает их обработчику заявок, и по результату обработки 
в заявку записывается статус (success или error) и результат работы обработчика.

### Установка
1. Склонировать себе сервис (git clone)
2. Запустить контейнеры (docker-compose up -d --build)
3. Сделать привязку в файле hosts домена mysite.local к 127.0.0.1
   Дальнейшие команды выполняются внутри контейнера php-fpm.
4. Зайти внутрь контейнера (docker-compose exec php-fpm bash)
5. Установить библиотеки composer (composer install)
6. Создать и заполнить файл .env (лучше просто сделать копию с файла env.example)
7. Обновить конфигурацию (php artisan optimize)
8. Запустить миграцию для создания БД и таблицы (php artisan migrate)


### Примеры запросов

#### Создание заявки 
    POST http://mysite.local/api/v1/leads/
    {
        "userName": "Иванов Петр",
        "email": "test@testemail.ru",
        "body": "Какая-то информация по заявке"
    }

Ответ:

    {
        "id": 7
    }

#### Получить статус заявки
    GET http://mysite.local/api/v1/leads/7/status

Ответ:

    {
        "status": "queued"
    }

#### Получить результат выполнения заявки
    GET http://mysite.local/api/v1/leads/7/result

Ответ:

    {
        "result": {
            "sum": 718,
            "status": "success",
            "message": "Заявка 7 успешно обработана!"
        }
    }
